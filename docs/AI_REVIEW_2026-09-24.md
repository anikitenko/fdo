Scope: the current uncommitted provider, request lifecycle, workspace generation, validation, settings, billing and regression-test changes. ## Findings corrected

1. **P1 — invalid OpenRouter reasoning payload.** The adapter sent `reasoning.effort` and `reasoning.max_tokens` together. The wire test asserted that same invalid shape. The gateway rejected it with HTTP 400. The adapter now uses a valid explicit token budget in preference to effort, checks that the budget leaves room for the answer, and strips both controls for explicit Off. [Provider contract](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).
2. **P1 — planning overrode the user's thinking setting.** The IPC path changed Off to On and raised the planning output budget to 8192. Removed that override. The built-app regression now checks Off, On and Auto across planning and multiple files, with three requests total and no hidden replay.
3. **P2 — all OpenRouter schemas were discarded.** This removed native enforcement even when a model supports it. Coding model inspection now passes catalog capabilities into the adapter. Models advertising `structured_outputs` receive the schema and require a supporting upstream; other models retain local validation. [Schema routing contract](https://openrouter.ai/docs/guides/features/structured-outputs).
4. **P2 — failure discarded trailing usage.** The Chat Completions adapter threw on `finish_reason: length` before consuming the following usage chunk. It now records final usage before raising the output-limit error. Buffered reasoning-only truncation preserves the same classification. No partial response becomes a completed result.
5. **Documentation drift.** Removed the accumulated trial narrative and accidental tool-edit fragments from the reliability guide. The guide now states the actual recovery boundaries and distinguishes deterministic protocol tests from a successful live scenario.

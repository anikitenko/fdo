The host injects window.FDOCharts (API version 1) into the plugin iframe. This is a host-owned, lazily loaded Recharts renderer, not the Recharts component API. Use it only in serialized frontend setup callbacks; never call it from backend render() or import it as an SDK export.

API:
const controller = await window.FDOCharts.create(element, config);
controller.update(fullReplacementConfig);
controller.dispose();

Config:
{
  type: 'line' | 'area' | 'bar' | 'pie',
  xKey: 'day',
  data: [{day: 'Mon', compute: 12, storage: 4}, {day: 'Tue', compute: 18, storage: null}],
  series: [
    {key: 'compute', label: 'Compute', color: '#22b8f0'},
    {key: 'storage', label: 'Storage', color: '#51cf66'}
  ],
  height: 280,
  label: 'Daily spending by resource category',
  theme: 'dark',
  stacked: false,
  legend: true
}

Allowed chart types are line, area, bar and pie. Pie requires exactly one series, uses xKey as the category label and a host palette for slice colors, and cannot have negative values. Stacking applies to area/bar. Use distinct xKey/series keys. Each data row must have a string or finite-number xKey value; series values must be finite numbers or null. Missing values become null; never turn missing telemetry into zero. Limit each chart to 10,000 rows and 12 series, aggregate larger datasets. Height must be 120–1600 pixels. Colors use six-digit hex. Configuration is data only: no formatter functions, JSX, callbacks, component props or arbitrary Recharts options. Dates and currency should have clear units in surrounding labels and accessible data summaries.

Use a dedicated empty connected HTMLElement for each chart. Its parent must have available width and min-width:0 in grid/flex layouts. The renderer sizes itself responsively; do not mount while its tab has display:none. Mount when that tab becomes visible, or ensure its container has positive width. For each chart show loading, empty and error states, a clear accessible label, units, and a readable data summary/table. Animations are disabled by the host. Charts are visualizations; controls and actions remain separate SDK UI elements. Resource dependency node/edge diagrams are outside this chart API.

Serialized callbacks must be self-contained: they cannot capture imported functions or backend module variables.

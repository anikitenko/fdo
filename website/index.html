BEFORE YOU START

Built in. Bring your own.
Know the difference.

Clear runtime requirements, from the desktop to a container.

Do I need to install an SSH client?

No. FDO includes its own SSH client on macOS, Windows and Linux. Configure credentials, trusted host keys and plugin permissions in FDO. Commands sent to a server must exist on that remote server.

Does GitOps require Git on my computer?

No. FDO ships a built-in Git runtime for its GitOps synchronization. Git or other CLI commands invoked by a plugin are different: those tools must be installed on the computer running FDO and allowed by the plugin’s process policy.

How do custom CLI tools work in a Docker export?

Declare the tools the exported app needs. The generated image can install catalog tools, Debian packages or verified executable downloads. Use a custom base image for vendor installers or full SDKs. The desktop’s installed tools are not copied. Read the Docker tool guide ↗

Can every plugin be exported automatically?

Conversion is reviewed before export. Supported source and services become a standalone frontend and backend; unsupported dependencies require migration work. Configure cloud access, credentials and persistent storage for the deployment. See export requirements ↗

Is FDO free and open source?

FDO is an open-source project distributed under the MIT license. Optional AI providers, cloud infrastructure and third-party services may have their own costs. You can use the built-in templates without making an AI request.

Where should I start?

Follow the beginner video workshops to build your first plugin and connect a real API. Install FDO 1.0.5, create a plugin from one of the ten built-in templates, and run its tests. Use the editor and Live UI to customize it, then sign and deploy it. The FDO CLI guide covers terminal workflows.
